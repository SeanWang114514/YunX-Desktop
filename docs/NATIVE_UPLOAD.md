# 桌面版原生上传交付说明

本次在 YunX-Desktop 原工程上增量增加上传，保留 Kotlin/JVM、Compose Desktop、原登录/目录页面、下载模块及打包结构。文件由桌面客户端通过网盘 API 和授权存储直接传输，不依赖网页上传、Android 模拟器或额外服务器。

## 2026-11-14 上传可靠性补强

- 失败项支持在详情和后台列表单独点击“重试”，批量“重试失败项”继续保留；重排后立即清除上一条失败原因、速度与进度采样，单项重试沿用原账号和目录，并遵守并发上限。
- 取消或账号错误在项目已选中但尚未启动的窗口内也会重新校验，避免取消后迟到任务仍发起写请求；并发补位和取消状态会立即刷新，不依赖下一轮定时采样。
- 目录分页把空游标、`-1`、重复游标和空页统一视为协议异常或结束条件，防止 123 等平台在末页后继续请求空页导致文件夹上传失败。
- 文件大小尚未解析时，批次显示“已发送 · 总大小未知”，不再把未知总大小误画成 0% 完成率；解析完成后恢复正常百分比与 ETA。
- 115 上传时的目录查找关闭打开时间记录和子项计数，只保留目录判断所需数据，减少大目录扫描开销。
- 本轮仍只编译和静态核对，不运行测试、不启动软件、不执行真实上传。
## 2026-11-14 上传失败重试

- 详情窗口和右下角后台卡片均提供“重试失败的 N 项”。上传过程中即可把失败项目重新排队，继续遵守设置中的并发上限；批次结束后的失败结果也保留重试入口。
- 仅重试失败的文件及目录，不重传成功项目，不重排取消项目；重置该项进度及失败原因后重新开始上传，不提供断点续传或自动无限重试。重传字节继续纳入整批速度，剩余时间按新的待传字节数更新。
- 沿用原账号、目录和上传协议，发起传输前重新核对账号。已确认成功的目录映射保留，失败目录在互斥保护下清理错误缓存并重新读取列表；等待旧任务清理完 I/O 后才允许重新排队，避免同一项目重复执行。
- 若上次失败发生在网盘确认阶段，重试前请先查看远端是否已保存，以免重复内容。已知账号错误停止接收后，须先恢复原账号再重试。
- 按要求仅编译、打包和静态核对，不运行测试、不启动应用、不执行真实上传。

## 2026-11-14 整批上传速度与剩余时间

- 总速度改为近五秒整批实际上传回调的字节增量除以采样时长，每半秒采样；跨文件、并发文件及目录任务连续统计，不再相加当前活跃文件的瞬时速度。不把建目录、秒传或服务端完成确认的进度跳变当作网络传输速度。
- 预计剩余时间采用整批尚待传输字节数除以总速度并四舍五入，不再因单个文件暂时无速度或批次正在准备下一个文件而隐藏。失败和取消项的未传字节不计入剩余工作；尚无有效采样或五秒窗口内无传输时显示 0 B/s，预计时间等待有效速度，避免虚构倒计时。此估算不预测建目录、计算校验及服务端确认耗时。
- 后台卡片和上传详情复用同一统计区域，显示整批已发送/总大小、总速度与预计剩余。后台统计移到限高滚动列表上方；时间数字保留 132 × 28 dp 固定区域和等宽字体。
- 保留上一版上传图标悬浮说明、仅拖拽时显示落点提示、文件和文件夹混选、并发设置及追加上传。未修改网盘上传协议。
- 本轮仅编译、打包及静态核对，未运行测试、未启动应用、未执行真实上传；统计准确性和实际界面效果由用户运行验收。

## 2026-11-14 上传悬浮提示与资源优化

- 移除默认常驻的上传提示栏和其中重复的选择按钮，将点击、混选、目录层级及追加说明放到上传图标的悬浮提示中。拖入本地文件时临时显示落点提示，离开或松开后收起；十个平台共用此行为。

- 后台扫描子文件夹，只读取元数据；保留所选根文件夹、子目录和空目录。扫描可取消，不跟随符号链接、目录联接或特殊文件，不直接上传磁盘根目录；跳过项会在确认窗口提示。
- 夸克、UC、迅雷、百度、移动云盘、123、115、光鸭、蓝奏和蓝奏优享均接入已有建目录 API。优先复用同名远端目录；同名文件阻挡目录、存在多个同名目录或无法确认分页时，相关项失败并显示原因。
- 目录映射限定原批次，建目录互斥，文件按设置并发传输。同名文件仅在目标相对路径相同时依次处理，不同子目录的同名文件可并行。文件重名、类型、大小及空文件限制仍沿用各网盘原有上传协议。

- 目录失败不会由其他排队文件自动重放建目录写请求；显式重试失败项时保留已确认成功的目录映射，并重新读取目录列表。取消只中止待传输内容，不删除已创建目录或已上传文件。

## 使用方法

1. 启动修改版，登录需要上传的网盘。
2. 进入个人盘目标目录，悬停右上角上传图标查看说明，点击后选择文件或文件夹；也可直接拖入文件列表。拖入时临时显示落点提示，松开后打开上传确认窗口。
3. 用“选择文件或文件夹”继续混合多选，无需切换选择模式；双击文件夹进入目录，选中文件夹后点击“选择”则添加整个文件夹。核对目标目录、文件数、目录数、总大小及相对路径，可移除文件或整个文件夹；点击“开始上传”才发送。此上传入口使用支持混选的 Swing JFileChooser，其他导入、保存及目录设置选择器保持原样。
4. 在“设置 → 上传 → 上传并发数”中选择 1–10 个文件（默认 3）。设置自动保存，按每个网盘分别计算，准备、传输和等待确认均占用并发位置。调高立即唤醒调度器并补充等待文件；调低不中断已开始的文件，随后按新上限排队。详情和后台卡片显示实际处理数量与上限，各文件分别显示等待、准备、传输、等待确认、完成或失败状态。进度条按整批字节数计算；速度为正在传输文件的合计速度（B/s、KiB/s、MiB/s 或 GiB/s），预计剩余按本批次尚未传输的总字节数估算，包含排队文件。剩余秒数四舍五入，时间数字使用固定宽高和等宽字体；采样不足时显示占位符。估算不包含尚未发生的哈希准备或服务端确认等待。“取消上传”停止本平台整个批次，退出程序也会中止。
5. 完成后查看成功、失败、取消及未开始数量，目录自动刷新。失败结果可点击“重试失败文件”，取消项需要重新选择。首次使用每个平台请先用可删除的小测试文件验证。

上传中点击进度窗口外的空白处、按 Esc 或点击“后台上传”，会收起详情，任务继续执行。主窗口右下角紧凑卡片显示完成数量、并发数量、文件名、整批进度、合计上传速度及预计剩余时间；时间沿用固定 132 × 28 dp、等宽数字及秒数四舍五入。卡片缩小上下内边距和行间距，字节详情保留在展开窗口中。点击卡片可重新展开详情并取消上传。切换目录、网盘或主导航页面后仍显示后台卡片；多个网盘同时上传时卡片纵向排列。这里的后台指应用内继续执行，退出程序仍会中止上传。

上传中右上角上传图标保持可用，点击后可继续选择多个文件；也可拖入文件到页面文件列表、上传详情、右下角进度卡片或文件确认列表。核对后点击“加入上传队列”，有空位时立即并发上传，达到设置上限时自动等待。详情与卡片的“添加文件”仍可使用。追加始终使用原批次固定的账号、目录和上传函数，不随当前浏览目录变化；同一真实路径在本批次中去重。确认窗口固定打开时的批次和提交动作，批次结束或停止接收后，迟到的确认不会把文件放进后续批次。不同目录的同名文件按顺序处理以避免同时覆盖，其他文件按配置填充并发位置。上限不等于实际传输数：文件不足、同名文件、准备或网盘确认阶段均可能导致实际传输数较少。

开始时固定目录与账号身份，同平台只允许一个可追加批次；上传期间限制该平台切号、添加及移除账号。普通文件失败后只标记该文件并继续处理其他排队文件，也继续接收追加；已知账号错误或用户取消时停止新任务。100% 字节不等于成功，须等待协议确认。

拖放通过 Compose Desktop 1.7.3 的原生 AWT 文件列表接入，只接受本地文件及文件夹，不把文本或网页链接当成上传文件。采用 COPY 拖放动作，保留本地源文件。递归保留文件夹结构；不存在、不可读取或链接项目会被跳过并提示。相同本地路径去重，不同目录的同名文件仍分别保留。上传和排队期间仍接受多个文件及文件夹拖入；加载中、扫描中、批量选择或其他无关操作弹窗时不接收。上传相关窗口内的拖入由该窗口处理，不会穿透到背后的页面。目录变化会关闭页面的预选确认窗口，防止目标变化。

- desktop/build.gradle.kts：登记测试、隔离测试偏好/目录及检测 VS 18。没有更换依赖版本或迁移数据库。
