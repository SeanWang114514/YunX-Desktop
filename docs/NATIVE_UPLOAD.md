本次在 YunX-Desktop 原工程上增量增加上传，保留 Kotlin/JVM、Compose Desktop、原登录/目录页面、下载模块及打包结构。文件由桌面客户端通过网盘 API 和授权存储直接传输，不依赖网页上传、Android 模拟器或额外服务器。

## 2026-11-14 本轮源码修订（未重新打包）

- 本轮仅静态检查，不编译、不运行测试、不启动应用。下文已有 EXE、JAR、编译和测试记录均为历史交付，不包含本轮修复；现有 release 目录保持原样。

- 普通文件失败不停止排队和追加。已知账号缺失、账号切换或凭据辅助函数明确报告失效时停止新任务；不按模糊错误文字猜测鉴权失败，也不把对象存储的签名错误一律当成账号失效。

- 批次结束后可仅重新排队失败文件，复用原目录和上传函数，并再次核对原账号身份。此重试需要用户点击，不自动重放整批；不重传已完成项，不包含取消项，也不提供重启恢复。

## 使用方法

1. 启动修改版，登录需要上传的网盘。
2. 进入个人盘目标目录，点击右上角的上传图标（鼠标悬浮约 0.5 秒显示“上传文件”），或拖拽本地文件到文件列表区域。拖入时提示区域高亮，松开后打开上传确认窗口。
3. 在确认窗口核对目标目录、文件数、总大小及文件列表，可添加或移除文件；点击“开始上传”才发送。Windows 文件选择器优先使用 COM 原生多选，不可用时回退 AWT 多选。
4. 在“设置 → 上传 → 上传并发数”中选择 1–10 个文件（默认 3）。设置自动保存，按每个网盘分别计算，准备、传输和等待确认均占用并发位置。调高立即唤醒调度器并补充等待文件；调低不中断已开始的文件，随后按新上限排队。详情和后台卡片显示实际处理数量与上限，各文件分别显示等待、准备、传输、等待确认、完成或失败状态。进度条按整批字节数计算；速度为正在传输文件的合计速度（B/s、KiB/s、MiB/s 或 GiB/s），预计剩余按本批次尚未传输的总字节数估算，包含排队文件。剩余秒数四舍五入，时间数字使用固定宽高和等宽字体；采样不足时显示占位符。估算不包含尚未发生的哈希准备或服务端确认等待。“取消上传”停止本平台整个批次，退出程序也会中止。
5. 完成后查看成功、失败、取消及未开始数量，目录自动刷新。失败结果可点击“重试失败文件”，取消项需要重新选择。首次使用每个平台请先用可删除的小测试文件验证。

上传中点击进度窗口外的空白处、按 Esc 或点击“后台上传”，会收起详情，任务继续执行。主窗口右下角紧凑卡片显示完成数量、并发数量、文件名、整批进度、合计上传速度及预计剩余时间；时间沿用固定 132 × 28 dp、等宽数字及秒数四舍五入。卡片缩小上下内边距和行间距，字节详情保留在展开窗口中。点击卡片可重新展开详情并取消上传。切换目录、网盘或主导航页面后仍显示后台卡片；多个网盘同时上传时卡片纵向排列。这里的后台指应用内继续执行，退出程序仍会中止上传。

上传中右上角上传图标保持可用，点击后可继续选择多个文件；也可拖入文件到页面文件列表、上传详情、右下角进度卡片或文件确认列表。核对后点击“加入上传队列”，有空位时立即并发上传，达到设置上限时自动等待。详情与卡片的“添加文件”仍可使用。追加始终使用原批次固定的账号、目录和上传函数，不随当前浏览目录变化；同一真实路径在本批次中去重。确认窗口固定打开时的批次和提交动作，批次结束或停止接收后，迟到的确认不会把文件放进后续批次。不同目录的同名文件按顺序处理以避免同时覆盖，其他文件按配置填充并发位置。上限不等于实际传输数：文件不足、同名文件、准备或网盘确认阶段均可能导致实际传输数较少。

开始时固定目录与账号身份，同平台只允许一个可追加批次；上传期间限制该平台切号、添加及移除账号。普通文件失败后只标记该文件并继续处理其他排队文件，也继续接收追加；已知账号错误或用户取消时停止新任务。100% 字节不等于成功，须等待协议确认。

拖放通过 Compose Desktop 1.7.3 的原生 AWT 文件列表接入，只接受本地文件，不把文本或网页链接当成上传文件。采用 COPY 拖放动作，保留本地源文件。文件夹、不存在或不可读取文件会被跳过并提示；相同真实路径去重，不同目录的同名文件仍分别保留。上传和排队期间仍接受多文件拖入；加载中、批量选择或其他无关操作弹窗时不接收。上传相关窗口内的拖入由该窗口处理，不会穿透到背后的页面。目录变化会关闭页面的预选确认窗口，防止目标变化。

## 增量代码位置

以下以 desktop/src/main/kotlin/com/yunx/app/ 为起点。

- util/WindowsFilePicker.kt、DesktopActions.kt：扩展原多选入口，保留单选/保存功能。
- 原十家 ViewModel / Screen：上传函数、按钮及共用 UploadProgressDialog.kt。
- UploadPane.kt、UploadSelection.kt：十页共用的拖放、预检、确认列表与上传状态界面，复用原上传执行器和 API。
- AccountDirectory.kt、MultiAccountViewModel.kt、MainScreen.kt、Main.kt：账号保护及退出取消。
- desktop/build.gradle.kts：登记测试、隔离测试偏好/目录及检测 VS 18。没有更换依赖版本或迁移数据库。
